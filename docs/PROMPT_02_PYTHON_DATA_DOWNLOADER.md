6.0 Order of work (dependencies): D12, then D01-D04, D09, then D07, D05, D06, D08, then D10, D11. D06 and D08 need D01 (day high/low) and D03 (VIX day high) already on disk; if missing, the command runs those first.
6.1 Chunking: V3 minutes 1-15: 28 calendar days (never above the P05 result); days: 3,000 calendar days; expired 1minute: `expired_1m_max_span_days` from the probe (default 1); expired day: one call per contract. The last chunk's to_date never exceeds TEST_END. For the expired endpoint with span 1, request ONLY trading days (skip weekends and holidays using the dated calendar), never calendar days.
6.2 Contract selection (point in time). For each underlying and each trading day D in the window (D06 uses WARMUP_OPTION_TRADING_DAYS_BY_INDEX before TEST_START):
  a) Expiry set for D: Get Expiries list (past) plus the instrument master (not yet expired). Current expiry = smallest expiry >= D. On a day equal to an expiry date also select the next expiry (the bot shifts to it at 13:30). Bank Nifty: current monthly contract, and the next monthly on its expiry day. Never compute expiry dates from weekdays. A monthly contract that expires after TEST_END (for example Bank Nifty November) is still selected for the days inside the window, through V3 historical because it is still listed.
  b) DELTA-AWARE strike band for D. step = smallest difference between strikes in that expiry's contract list. cal_dte = max(0.5, calendar days from D to expiry). margin_pts = max(STRIKE_MARGIN_STEPS x step, STRIKE_DELTA_MARGIN_K x spot_close(D) x (VIX_day_high(D)/100) x sqrt(cal_dte/365)). Band = all listed strikes K with day_low(D) - margin_pts <= K <= day_high(D) + margin_pts, CE and PE. Reason: a flat 6-step margin misses the delta 0.45-0.65 strikes of long-dated contracts (a Bank Nifty monthly 3 weeks out needs roughly 9 steps ITM), so the margin must grow with sqrt(time). day_low, day_high, spot_close and VIX_day_high come from already-downloaded D01 and D03 data (download-time superset, never a strategy decision). D08 uses the same formula with WIDE_CHAIN_STEPS x step as the minimum margin.
  c) A contract is "listed on day D" only if its expiry >= D and its first returned candle date <= D (`contract_first_seen`). A contract in today's master but absent from the expired list for an expired expiry is logged `MASTER_ONLY` and never used for past days.
  d) Contract-level spans: for each contract take the days on which it was selected. With cap 1 call only the selected days. With a larger cap request first_selected..last_selected in cap-sized chunks (gap days come for free inside a call).
  The downloader first builds `selection_plan.parquet` (underlying, expiry, key, strike, option_type, days, chunks) and prints counts and the estimated runtime (calls / rate per minute) before any call; `plan` prints the same without calling anything. Expected scale (ESTIMATE): about 5,000-6,500 option calls with a 28-day cap; about 22,000-28,000 with a 1-day cap (hours at 30 per minute: roughly 3 to 16).
6.3 Raw storage: every successful response goes to `raw/<item_id>/<instrument_hash>/<from>_<to>.<fetch_run_id>.json.gz` (a run id in the name lets a re-fetch coexist; the latest DONE file wins; a file is never overwritten; a second write to the same name raises), with a sidecar `.meta.json` (request path without token, HTTP status, UTC fetch time, sha256 of the body, byte size, header names of interest). Writes are atomic: temp file in the same folder, fsync, os.replace. File names contain no colons.
6.4 State: SQLite `state/progress.sqlite3`. Two tables: `chunk_status` keyed by (item_id, instrument_key, from, to) with DONE, EMPTY_OK, FAILED_RETRYABLE, FAILED_PERMANENT, INCOMPLETE; and `coverage` keyed by (instrument_key, trading_date) for every day covered by a DONE or EMPTY_OK chunk. Planning consults `coverage`, so changing the chunk size later never re-downloads a covered day. A chunk is DONE only after the raw file is written and its sha256 recorded. Re-running skips covered days, retries failed chunks, and verifies sha256 of existing raw files.
  Fresh-data safeguard: the most recent trading day in the window is re-fetched once on the NEXT run (`--refetch-last-day`, default on) because the last session can still be revised.
6.5 Normalisation: write Parquet (zstd), one file per (table, underlying, trading_date) under `store/<partition>/<table>/underlying=<U>/trading_date=<YYYY-MM-DD>/part-0.parquet` (built by merging chunks in a `compact` step; never one file per chunk) with these columns exactly: instrument_id (string), instrument_key (string), underlying (string), segment (string), expiry_date (date or null), strike (float or null), option_type (CE/PE/FUT/SPOT/null), interval (string), ts_open (timestamp, Asia/Kolkata), ts_close (timestamp; ts_open plus interval; for daily candles ts_open date 23:59:59.999 IST), o, h, l, c (float64), v (nullable Int64), oi (nullable Int64), has_volume (bool: false for index, VIX and global instruments), is_stale (bool: true only when has_volume is true AND v == 0; always false when has_volume is false), is_filled (bool, always false in raw tables), session_type (string from the session table), trading_date (date), source ("upstox_v3" or "upstox_expired_v2"), adjusted_status (string), fetch_run_id (string), raw_sha256 (string). Partition is `holdout` when trading_date >= HOLDOUT_START, else `dev`. The same column set is the schema for the owner's future Recorder snapshots; the Recorder adds bid, ask, bid_qty, ask_qty, iv_source, exchange_ts, local_ts, all null in historical rows.
  Volume unit (contracts vs lots vs shares) is UNVERIFIED: store `volume_unit=UNVERIFIED` in table metadata; the validator's bhavcopy reconciliation (8.5) is what resolves it.
6.6 `--dry-run`: zero network calls, zero writes outside a temp folder, prints the selection plan and call counts. A test patches the HTTP layer to raise on any call.
6.7 DATA_RIGHTS: OK = store everything; MINIMAL = delete raw files after normalising, keep derived tables plus the OHLC they need; NOT_ALLOWED = abort with exit code 40 before any call; UNVERIFIED (default) = store locally, print at the start of every command the Hinglish warning "Data sirf apne use ke liye hai. Kisi ko mat do. Upstox se likhit jawab lo." and write `DATA_RIGHTS_UNVERIFIED.txt` into the store folder.

# 9. DERIVED TABLES (stage 3): `python -m updl derive`
Every derived column name ends with `_DERIVED`, every proxy column with `_PROXY`; table metadata `look_ahead_rule` = "uses only bars with ts_close <= decision time"; every derived or daily-level row has `available_from_ts` (rule 8). Dev and holdout trees are derived by the same code in date order; the derive step for a dev day must never read a holdout row (holdout days may read earlier dev days as history). Derived bars are emitted only after their last 1-minute bar exists.
 9.1 `bars_3m`, `bars_15m` from 1-minute spot bars (buckets start at 09:15; a bucket not holding all its minutes is `is_partial=true`, excluded from signals).
 9.2 Reconstructed chain per minute: per underlying, minute and expiry, a row per selected strike with CE and PE close, volume, OI, is_stale. Strikes outside the band are absent, never estimated.
 9.3 IV and Greeks (`reference/iv_model.yaml`, tag ASSUMPTION; the owner has not fixed the model): Black-76 on a forward F. Default forward source `PARITY_THEN_COST_OF_CARRY`: per minute and expiry take the strike where |C-P| is smallest among non-stale CE/PE pairs and set F = K + C - P; when no such pair exists use F = S x exp(r x T) with S = same-minute spot close, r = 0.065, q = 0. Column `forward_source` records which was used. T = (settlement time - bar ts_close) / 525,600 minutes (calendar-time convention, ASSUMPTION), settlement 15:30 on the expiry date until 2026-07-31 and 15:40 from 2026-08-03 (ASSUMPTION), with T clamped to at least 1 minute. Bracketed root finding on the option close. Columns iv_DERIVED, delta_DERIVED, gamma_DERIVED, theta_DERIVED, iv_status (OK, BELOW_INTRINSIC, NO_SOLVE, STALE_PRICE). is_stale rows get STALE_PRICE and no IV. README: these are computed, not broker values.
 9.4 `iv_daily_DERIVED` (ATM IV at 10:00 and 14:00, `available_from_ts` = those times, with DTE bucket) and `ivp_vix_PROXY`: the percentile rank of the India VIX value known at decision time (previous trading day's close for the whole of day D; the latest 1-minute VIX close <= decision time for intraday use) among the PREVIOUS 252 daily closes, never including the current day. Needs >= 252 trading days of daily VIX before the row; otherwise `ivp_status=INSUFFICIENT_HISTORY` and null.
 9.5 `rv20_DERIVED` (20-day realised volatility from daily closes, annualised with 252; value for day D uses closes up to D-1 for intraday use, `available_from_ts` of the D-inclusive version = D 15:30), `pcr_DERIVED` (sum put OI / sum call OI over the band and over the wide chain separately), `oi_walls_DERIVED` (largest call-OI strike above spot, largest put-OI strike below spot, per minute), `max_pain_DERIVED` (expiry day only), `gex_proxy_PROXY` (gamma x OI x lot_size x spot^2 x 0.01, calls positive, puts negative; dealer-side assumption), `gamma_flip_PROXY`, `skew_DERIVED` (IV of the strike nearest +0.25 delta put minus the strike nearest 0.25 delta call), `vix_term_DERIVED` (near-expiry ATM IV minus next-expiry ATM IV), `breadth_PROXY` (weighted advance/decline from `constituents.csv` and stock bars; absent file -> column not created).
 9.6 Volume baselines. The owner's rule is "previous 5 trading days, same minute of day, same moneyness bucket (signed, 1-step buckets of (strike - spot)/step rounded) and same days-to-expiry bucket (0, 1, 2, 3-4, 5-7, 8-14, 15-30, over 30 trading days)". CAUTION: on a weekly contract the previous 5 trading days never share today's DTE bucket (each day is one day closer to expiry), so the literal rule has no matches for DTE 0-2. Therefore two columns are written (VOLUME_BASELINE_MODE=BOTH):
   `volume_baseline_same_dte_DERIVED`: mean over the previous 5 OCCURRENCES of the same DTE bucket at the same minute and moneyness bucket (for weekly contracts that means the same weekday-phase of earlier weeks; needs the 35-day option warm-up; Bank Nifty monthly DTE 0 has no history: null with `baseline_status=NO_HISTORY`).
   `volume_baseline_any_dte_DERIVED`: mean over the previous 5 trading days regardless of DTE, same minute and moneyness bucket (works with 7 warm-up days).
   Never match by strike name across days. Missing history gives null plus `baseline_status`.
 9.7 `fill_assumptions_PROXY`: per option minute `modelled_ask_PROXY = close + half_spread_PROXY`, half_spread_PROXY = max(tick_size, 0.5% of close); `fillable=false` when v == 0 or no candle. Fill rule: next bar with v > 0 at max(close, modelled ask); never a carried-forward last price. Same-minute stop and target: stop first (documented in SCHEMA.md).
